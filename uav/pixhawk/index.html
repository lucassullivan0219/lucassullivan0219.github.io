  2. MAVSDK → SITL。Gazebo 模擬用 make px4_sitl gz_x500 啟動，機型就是 x500。PX4 Gazebo
  3. 電腦 → 數傳 → 飛控。PX4 的「只有飛控」架構就是地面站經數傳電台連飛控，地面站可跑 QGroundControl 或 MAVSDK。PX4 系統架構
  4. 伴隨電腦（之後）。樹莓派用 UART 接飛控，延遲低，適合影像與即時運算。RPi Pixhawk Companion

每個分岔的依據

  1. 韌體選 PX4。套件 shipped with PX4 open-source firmware 商店頁；PX4 文件寫 DroneKit is no longer recommended.，建議改用 MAVSDK。PX4 DroneKit 頁 MAVSDK 對 ArduPilot 是逐項補上的相容。MAVSDK 文件
  2. 買套件。PX4 文件說套件的零件 are known to work well together Kit Builds；ArduPilot 論壇老手觀察，起飛就翻幾乎都是馬達順序或轉向問題（見第 4 段災情）。
  3. X500 v2 而非 Starling／DEXI。三款都是官方認證開發套件。PX4 Dev Kits DEXI 5 特價 $2,149–2,645 DroneBlocks 商品頁；Starling 2 Max 單機 $4,199.99 起。ModalAIX500 v2 能載 1.5 kg，PX4 文件形容它是加裝自己伴隨電腦與感測器的好底座。PX4 Dev Kits推論DEXI 5 約是 X500 v2 的 3.5 倍、Starling 2 Max 約 7 倍，且你之後要自己加感測器，X500 v2 最合適。
  4. 6C 而非 6X。兩者價差 $160。商店頁 推論入門與 Python 控制用不到 6X 的冗餘 IMU；6X 改附數位電源模組，還多一步參數設定。
  5. 數傳先查證。依據與替代方案見第 3 段。
  6. 遙控接收機選 SBUS。PX4 預設韌體不含 CRSF，要自己編譯。PX4 CRSF
  7. 分階段。SITL 不用硬體；地面電腦＋數傳的遙測延遲較高；伴隨電腦延遲低。依據見上方資訊流第 2–4 點。
  8. 室內加光流。H-Flow 整合光流、ToF 測距與 IMU，PX4 和 ArduPilot 都能設定。Holybro 文件

範圍怎麼界定

「所有常見套件」沒有官方總表，所以先寫清楚這頁算進哪些、不算哪些，再列結果。

  • 算進來：買得到、含飛控與機體、出廠跑 PX4 或文件寫可跑 PX4 的多旋翼套件或開發機。
  • 飛控怎麼分：PX4 文件把飛控分成「Pixhawk 標準飛控」（如 Pixhawk 6C、6X、6C Mini）與「廠商支援飛控」（如 ARK Pi6X Flow、ModalAI VOXL 2）。Pixhawk 標準 廠商支援 官方認證開發套件的條件之一是飛控 meets the latest Pixhawk standard, or matches its capabilities PX4 Dev Kits，所以後者也列入。
  • 查證角度：① PX4 官方認證開發套件頁 ② PX4 Kit Builds 頁 ③ PX4 Complete Vehicles 頁 ④ Holybro 商店 ⑤ 各原廠頁面。至少兩個角度出現才算「常見」。
  • 不算進來：跑客製 PX4 的消費型空拍機、FPV 競速機、固定翼與 VTOL、只賣飛控不賣機體的商品、以 ArduPilot 為主推的套件。

先決問題：數傳頻段在台灣能不能用

這是 Crazyflie 沒有、PX4 套件才有的問題。Crazyflie 走 2.4 GHz；X500 v2 套件附的 SiK 數傳只能選 433 或 915 MHz。

選項硬體頻段台灣低功率射頻技術規範（LP0002）怎麼說我的判斷
SiK 433 MHz 版414–460 MHz 規格 433–435 MHz 用於傳送控制訊號，不得用於連續性傳輸，例如遙控玩具或傳送資料。LP0002 第 4.4.2.4 點 推論數傳要連續送遙測，不符合這一條。不建議。
SiK 915 MHz 版902–928 MHz，20 dBm 可調 規格 920–928 MHz 給 RFID；其他種類物聯網器材：920 MHz～925 MHz；這一類要用跳頻或數位調變，最大峰值輸出功率室外 0.5 W、室內或特殊場所 1 W。LP0002 第 5.8 點 2023 修正公報 推論出廠的 902–928 MHz 跳頻範圍超出 920–925 MHz。SiK 是跳頻，可改頻率範圍與功率 經銷商頁；設在 920–925 MHz、20 dBm（0.1 W）時，技術條件看起來落在規範內。但自行改設定的進口器材算不算合格、能不能用切結進口，我沒查到 NCC 明文。要問 NCC 台灣翔大有賣 SiK V3（NT$2,800），商品頁寫「非隨插即用之射頻零組件模組」、沒標 NCC 審驗 翔大，這不代表可以合法使用。
Wi-Fi 數傳（ESP32）2.4 GHz Wi-Fi；Wi-Fi 模式約 50–200 m PX4 ESP32 屬一般 Wi-Fi 頻段。 推論法規風險最低、距離最短。校園內實驗距離通常夠用。

推論：建議做法下單前先用電話或 email 問 NCC：「915 MHz SiK 數傳以自用切結進口，設定在 920–925 MHz、20 dBm 以下，可否使用？」若答案是否定的，就仍買整套（數傳留著不用，或只在模擬與桌上測試用），另外加一顆 ESP32 做 Wi-Fi 數傳；或改買「X500 V2 ARF 機架 $329＋Pixhawk 6C（含 PM02）$217.99＋M10 GPS $43.99」分開組，不含 SiK，合計 $590.98，只比整套便宜約 $18。ARF 6C M10 價差這麼小，直接買整套比較省事。

供貨風險RTK 廠商 ArduSimple 在 2025-07-23 發文，說 Holybro 官網當時公告所有出貨延遲，原因是 unexpected operational delays。ArduSimple 那是一年多前的事；Holybro 官網目前可正常下單，只公告 9/30–10/7（香港時間）辦公室休假，期間訂單回來後處理。Holybro 商店頁 遙控器 TX16S、PX4 Vision、伴隨電腦底板等部分品項目前缺貨，下單前建議先寫信確認出貨時程。

import asyncio
from mavsdk.asyncio import Mavsdk, Configuration, ComponentType
from mavsdk.asyncio.plugins.action import ActionAsync
from mavsdk.asyncio.plugins.telemetry import TelemetryAsync

async def run():
    mavsdk = Mavsdk(Configuration.create_with_component_type(ComponentType.GROUND_STATION))
    # SITL；實機數傳改成 "serial:///dev/ttyUSB0:57600"（Windows 為 "serial://COM3:57600"）
    await mavsdk.add_any_connection("udpin://0.0.0.0:14540")
    drone = await mavsdk.first_autopilot(10.0)
    if drone is None:
        raise SystemExit("找不到飛控：確認 SITL 在跑、連線字串正確")

    async for health in TelemetryAsync(drone).subscribe_health():
        if health.is_global_position_ok and health.is_home_position_ok:
            break

    action = ActionAsync(drone)
    await action.arm()
    await action.takeoff()      # arm 後幾秒內要起飛，否則會自動解除武裝
    await asyncio.sleep(10)
    await action.land()

asyncio.run(run())

連線字串格式（udpin://、serial://、Windows 的 COM3）與 SiK 範例鮑率 57600 都出自 MAVSDK 連線文件。Connections 指令被飛控拒絕時（例如還沒定位就 arm），4.x 會直接丟出例外，例如 ActionError。Quickstart 推論這段程式我只在本機確認過 4.0.3 的 import 與 API 名稱，沒有接 SITL 實際飛過。

骨架程式 推論：未實測

先起飛，再進 Offboard 以機體座標速度控制；get_decoded_command() 留給你接自己的 BCI 輸出。

import asyncio
from mavsdk.asyncio import Mavsdk, Configuration, ComponentType
from mavsdk.asyncio.plugins.action import ActionAsync
from mavsdk.asyncio.plugins.offboard import OffboardAsync, VelocityBodyYawspeed

V = 0.3                                    # m/s，先用慢速
CMD = {'forward': (V, 0), 'left': (0, -V), 'right': (0, V), 'rest': (0, 0)}
ZERO = VelocityBodyYawspeed(0.0, 0.0, 0.0, 0.0)

async def get_decoded_command():
    """接你的 BCI 輸出（LSL marker、socket…），回傳 (label, confidence)"""
    raise NotImplementedError

async def run():
    mavsdk = Mavsdk(Configuration.create_with_component_type(ComponentType.GROUND_STATION))
    await mavsdk.add_any_connection("udpin://0.0.0.0:14540")
    drone = await mavsdk.first_autopilot(10.0)
    if drone is None:
        raise SystemExit("找不到飛控")
    action, offboard = ActionAsync(drone), OffboardAsync(drone)

    await action.arm()
    await action.takeoff()
    await asyncio.sleep(8)

    await offboard.set_velocity_body(ZERO)          # 進 Offboard 前先送一次
    await offboard.start()

    loop = asyncio.get_running_loop()
    t_end = loop.time() + 60                        # 最長 60 秒
    while loop.time() < t_end:
        try:
            label, conf = await asyncio.wait_for(get_decoded_command(), 0.1)
        except asyncio.TimeoutError:
            label, conf = 'rest', 0.0
        vx, vy = CMD.get(label, (0, 0)) if conf >= 0.7 else (0, 0)
        await offboard.set_velocity_body(VelocityBodyYawspeed(vx, vy, 0.0, 0.0))
        await asyncio.sleep(0.1)                    # 約 10 Hz，高於 2 Hz 門檻

    await offboard.set_velocity_body(ZERO)
    await offboard.stop()
    await action.land()

asyncio.run(run())

推論：實驗注意X500 v2 槳徑約 10 吋、帶電池約 2 kg，遠比 Crazyflie 危險；BCI 實驗建議受試者與飛行區之間有防護網，並由另一人拿遙控器隨時接管。馬達與數傳也可能在 EEG 上造成雜訊，先在無人機運轉、受試者靜止時錄基線。

同一空間多架一起飛，會不會互相干擾？

法規

台灣規定操作人不得在同一時間控制 2 架以上遙控無人機；學校可另向民航局申請核准。民用航空法第 99-14 條 民航局回覆學校時也說，群飛屬於這項操作限制，即使在綠區也要另外處理。民航局回覆 推論多機實驗先在 SITL 做，實機要問民航局。

無線電

每對 SiK 有自己的 Network ID，可在地面站修改。經銷商頁 推論多機時每對設不同 Network ID，並在 PX4 把每架的 MAVLink system ID 設成不同值，MAVSDK 才分得出是哪一架。PX4 Gazebo 有多機模擬可先練。Multi-Vehicle Sim

氣流

推論500 mm 級四軸的下洗氣流很強，不要讓兩架上下重疊；水平距離至少留數個機身寬。
